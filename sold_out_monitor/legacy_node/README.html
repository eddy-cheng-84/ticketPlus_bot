TicketPlus 監控說明

TicketPlus 有票通知器

這份工具會定期檢查 TicketPlus 頁面上的指定場次，只要某一天從「銷售一空」變成有票，就會送出 ntfy 通知。

目前通知格式長這樣：

2026-06-20 有票 [2026-06-16T12:34:56.789Z]

1. 最快開始方式

第一次使用請先安裝依賴：

cd C:\Users\Lu_white\Documents\Codex\2026-06-16\hi\work\ticketplus-monitor
npm.cmd install

之後直接執行監控：

start-monitor.bat

如果只想先測試通知：

test-notify.bat

2. 它現在會做什麼

  • 打開 TicketPlus 活動頁面。
  • 固定檢查你指定的場次文字。
  • 如果某一天不再顯示「銷售一空」，就發 ntfy。
  • 同一個狀態不會每一輪都重複通知。

3. 最常改的設定

WEBHOOK_URL ntfy 的 topic 網址。
POLL_MS 輪詢間隔，單位毫秒。
60000 = 60 秒。
POLL_MIN_MS / POLL_MAX_MS 隨機輪詢區間。
例如 45000 到 90000。
HEADLESS true = 背景執行不顯示瀏覽器。
false = 看得到瀏覽器。
FAST_MODE true = 同一頁一直 reload。
false = 每輪重開一頁。
ALERT_REPEAT_COUNT / ALERT_REPEAT_INTERVAL_MS 有票時重送通知次數與間隔。
預設 3 次，每次 60 秒。

4. 如果要改成其他網站

最少要改這幾個地方：

  • TICKETPLUS_URL：改成新網址。
  • TARGETS：改成你要監控的場次或目標文字。
  • 判斷「售完 / 有票」的文字規則。
  • 等待頁面載入完成的條件。
如果只是同一個 TicketPlus 站內的別場活動，通常先改網址和目標場次就夠了。
如果是完全不同網站，解析規則通常也要一起改。

5. 隨機輪詢怎麼設

如果你不想固定每 60 秒檢查一次，可以改成區間隨機。

set POLL_MIN_MS=45000
set POLL_MAX_MS=90000

這樣每一輪都會在 45 到 90 秒之間隨機挑一個等待時間。

如果你想回到固定間隔，就只用：

set POLL_MS=60000

6. 為什麼現在用 Fast Mode

目前預設是 FAST_MODE=true，也就是固定同一頁一直 reload()。

  • 比較省資源。
  • 輪詢速度比較快。
  • 比較適合這種長時間掛著跑的監控。

如果哪天你發現網站容易卡住、判斷怪怪的，可以改成：

set FAST_MODE=false

這樣每次都會重開新頁，穩定性通常比較高。
