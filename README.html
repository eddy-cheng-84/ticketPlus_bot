Ticket Plus Bot

Chrome / Edge Chromium Manifest V3 擴充功能，透過右側 Side Panel 控制 Ticket Plus 的活動入口、票區選擇、加票與下一步。

目前主要開發分支：dev

支援頁面

活動頁/activity/...
啟動後尋找並點擊「立即購買」或「尚未開賣」。
搶票頁/order/...
執行更新票數、選區、點加號、專屬碼與下一步。
結帳頁/confirmSeat/...
偵測到後停止自動流程，不再操作頁面。

安裝

  1. 開啟 Chrome 的 chrome://extensions/ 或 Edge 的 edge://extensions/。
  2. 開啟「開發人員模式」。
  3. 選擇「載入未封裝項目」並選取：C:\Users\Lu_white\Documents\chrome_extension\ticket_plus_bot
  4. 開啟 Ticket Plus 頁面，點擊工具列圖示開啟右側 Side Panel。
  5. 修改程式後，先在擴充功能管理頁按「重新載入」，再重新整理 Ticket Plus 分頁。

GUI 設定

設定用途
讀取票區清單更新票數後掃描整頁票區，包含整頁捲動後才出現的區域。
全選 / 取消全選控制要納入自動選擇的票區；勾選後可調整上移/下移優先順序。
幾張票每輪點擊 + 的次數，限制為 0 到 4。
專屬碼／優先購票碼點完 + 後才填入；留白表示不啟用。
點擊更新票數 delay 秒數記錄更新票數的開始時間。等待期間仍可同步讀取票區與嘗試選擇。
選區後延遲幾秒按 +點進票區後等待 DOM 展開，再開始點擊加號。
選擇順序支援 top_to_bottom、bottom_to_top、middle、random。
每日自動啟動/暫停使用 24 小時制 HH:MM:SS，例如 12:00:00 是中午 12 點。

按下啟動後的流程

  1. /activity/...：點擊「立即購買」或「尚未開賣」；找不到時寫 Log 並等待下一輪。
  2. /order/...：點擊「我知道了」（如果存在），再點擊「更新票數」。
  3. 以更新票數的時間點 A 計算 delay，同步讀取票區。
  4. 先套用 GUI 勾選清單，再套用選擇順序。
  5. 有「剩餘 N」且 N 大於 0 的區域可選；「熱賣中」即使沒有明確剩餘數，也視為可嘗試；明確「剩餘 0」會跳過。
  6. 點選票區，等待選區後延遲，依設定張數點擊 +。
  7. 多張票的 + 之間間隔 50ms；點完後再等 50ms 才填專屬碼。
  8. 填碼後等待 100ms，點擊「下一步」。
  9. 下一步後最多觀察 5 秒。排隊頁只等待自動跳轉；進入 /confirmSeat/... 則停止流程。
  10. 尚未成功時寫入 Log，回到下一輪；下一輪在達到 A 的 delay 後才再次更新票數。

票區與專屬碼 selector

票區標題使用 button.v-expansion-panel-header，加號使用包含 i.mdi.mdi-plus 的按鈕。票區名稱比對前會移除票數、價格與狀態文字，避免更新後名稱不一致。

專屬碼不依賴會變動的動態 id，例如 input-597，目前依序尋找：

  • .exclusive-code .v-text-field__slot input
  • .exclusive-code input[type="text"]
  • .exclusive-code textarea
  • placeholder 或外層文字含有 PRESALE、MEMBERSHIP、序號、專屬碼、優先購票碼 的輸入欄位

填入後會派送 input 與 change 事件，讓 Vue / Vuetify 收到內容。找不到專屬碼欄位時只略過填碼，不會讓整個流程失敗。

Log 篩選

Side Panel 的 Log 可以勾選：成功、票況、失敗、掃描細節、系統。

要確認「到底掃描到哪些區域」，請打開「掃描細節」。Log 會列出初始區域、每次整頁捲動後的實際區域列表，以及最後合併結果。

外部 HTTP 觸發

啟動 Python server

python trigger_server.py

預設服務：http://127.0.0.1:16888/trigger

  1. Side Panel 勾選「啟用外部 HTTP 觸發」。
  2. URL 填入上面的位址，選擇 GET 或 POST。
  3. 設定輪詢秒數，最小為 0.5 秒。
  4. 按「儲存外部觸發設定」。

GET 測試

開啟 http://127.0.0.1:16888/trigger?fire=1，或按 Side Panel 的「立即測試外部觸發」。這會暫存一次性 trigger，擴充功能下一次輪詢取到後，對尚未執行中的 Ticket Plus 分頁送出啟動指令。

POST 測試

Invoke-RestMethod `
  -Method Post `
  -Uri http://127.0.0.1:16888/trigger `
  -ContentType "application/json" `
  -Body '{"trigger":true,"id":"job-001"}'

POST 也可以用 options 覆蓋本次執行設定：

{
  "trigger": true,
  "id": "job-002",
  "options": {
    "selectedTargets": ["A區"],
    "orderMode": "top_to_bottom",
    "plusCount": 2,
    "exclusiveCode": "ABC123",
    "refreshToAreaDelayMs": 1500,
    "areaToPlusDelayMs": 300
  }
}

沒有提供 options.exclusiveCode 時，會沿用 Side Panel 儲存的專屬碼。

外部觸發沒有反應時

  1. 確認 trigger_server.py 的視窗仍在執行。
  2. 開啟 http://127.0.0.1:16888/trigger?fire=1，確認回傳 armed: true。
  3. 確認 Side Panel 的 URL、方法、輪詢秒數已儲存且顯示啟用。
  4. 重新整理 Ticket Plus 分頁，確認 Log 出現「內容腳本已載入，等待指令」。
  5. 查看 Log 是否有外部觸發錯誤或 NO_TICKETPLUS_TAB。

Python server 只負責暫存與回傳 trigger；真正啟動流程的是擴充功能的 background script 與 content script。

主要檔案

  • manifest.json：MV3、Side Panel、權限與 content script。
  • popup/popup.html：Side Panel GUI。
  • popup/popup.js：GUI 設定、票區清單、外部觸發測試與 Log 篩選。
  • content.js：DOM 掃描、票區選擇、加號、專屬碼、下一步與頁面狀態。
  • background.js：外部 HTTP 輪詢、觸發去重與分頁啟動。
  • trigger_server.py：本機 GET / POST trigger server。

node --check content.js
